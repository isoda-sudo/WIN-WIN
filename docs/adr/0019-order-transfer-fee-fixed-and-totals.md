# ADR-0019: 発注の振込手数料をレコード生成時に固定し、金額の集計と粗利に含める

## メタ情報

- **ステータス**: 提案中(Proposed)
- **日付**: 2026-10-27
- **決定者**: Claude Code（承認: 人間レビュアー）

## コンテキスト（背景と課題）

ADR-0012 では、発注の振込手数料を、選択した支払元口座の手数料ルールから、一覧の表示のたびに算出していた。そのため、ルールを変えると、支払済みの発注の手数料の表示も変わった。また、手数料は一覧の専用の列にだけ出て、上の月間サマリや粗利には含まれていなかった。顧客から、次の指摘があった。

- 手数料は、レコードを作った時点で固定すること
- 手数料を含めた金額と粗利で計算すること（レポーティングを含む）
- 支払元口座は、「未選択」にならず、必ずデフォルト口座があること

## 決定内容

**手数料の固定**（`orders.transfer_fee`）

- 発注のレコード作成時に、決定額（なければ予算額、見積額）と、支払元口座（未設定はデフォルト口座）、発注先の銀行から手数料を算出して保存する
- 以後、手数料ルールを変えても、保存済みの値は再計算しない
- 算出し直すのは、(1) まだ算出されていない（空）とき、(2) 支払前に、支払元口座または発注先を変えたとき。支払済みの手数料は変えない
- 期をまたぐコピーで作る発注は、新しいレコードとして、その場で算出する（コピー元の値は引き継がない）
- 工事外の支払（`misc_payments`）は、従来どおり支払済みで固定される

**支払元口座**: 「未選択」を選択肢から外した。未設定の行は、デフォルト口座として表示し、手数料もデフォルト口座で算出する（保存時・一覧の算出の両方）。

**手数料を含める集計**（`src/lib/order-cost.ts` の `orderCostTotal` ＝ 決定金額 ＋ 振込手数料）

- 支払い予定表の月間サマリ（当月支払予定額・当月支払実績額）。実績額は、支払済みの発注の決定金額と手数料
- 工事外の月間サマリも、各行の手数料を含める
- レポーティングの粗利 ＝ 売上（案件の契約金額）− （発注の決定金額 ＋ 振込手数料）の合計。顧客別分析、案件別、5期推移が対象
- 工事計画の外注費合計・想定利益額・想定粗利率（予定金額の側も同様）
- 支払CSVに、「振込手数料」の列を追加（支払金額は決定金額のまま）
- **含めないもの**: 発注先別分析（偏り・集中度）は、決定金額のまま

## 影響

### ポジティブ

- 支払済みの手数料が、ルール変更で変わらない
- 月間サマリと粗利が、実際の支出（手数料込み）に近づく

### ネガティブ

- 金額が決まる前に作った発注の手数料は、予算額・見積額で見込んだ値で固定される（金額帯が変わると、実際の手数料と違う可能性がある。支払前に口座・発注先を変えると、算出し直される）
- 既存の発注175件には、実装時点のルールで、一度だけ値を埋めた（`scripts/backfill-order-transfer-fee.ts`）

### フォローアップタスク

- [ ] 発注の金額（決定額）が変わったときに、手数料を算出し直すか、決める
