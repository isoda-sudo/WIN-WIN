# ADR-0008: 受注一覧の表示仕様（期タブ・ID昇順・金額読み取り専用）と期跨ぎのコピー移行

## メタ情報

- **ステータス**: 提案中(Proposed)
- **日付**: 2026-10-13
- **決定者**: Claude Code（クライアント要望の反映。承認: レビュアー）

## コンテキスト（背景と課題）

クライアントから受注一覧について次の要望があった。

1. 期タブの「全期間」を無くし、期ごとの表示だけにする。
2. 表示順を案件IDの昇順（若い順）で固定する。
3. 予定売上・契約金額は工事計画から自動反映し、受注一覧では手入力させない（D-14）。
4. 引渡月の変更が会計年度（4/1〜3/31）を跨ぐ場合は、移動ではなくコピーとして新しい期へ引き継ぐ。

従来の引渡月変更（projects.changeDeliveryMonth）は、新しい案件IDを採番したうえで旧案件の発注・請求書・ファイルを
すべて新案件へ付け替える「移動」だった。期をまたぐと旧期の実績（請求書・支払）が旧期から消えてしまう。

## 検討した選択肢

### 選択肢A: 常に移動（現状維持）

- 長所: 実装済み。二重計上が起きない。
- 短所: 旧期に属する請求書・支払の履歴が新期へ移ってしまい、期ごとの集計が変わる。

### 選択肢B: 期跨ぎのみコピー、同一期内は従来どおり移動

- 長所: 旧期の実績は旧案件に残る。同一期内の変更は従来どおり。
- 短所: 旧案件（オーダー移行）の発注が残るため、集計側で除外しないと二重計上になる。

### 選択肢C: 期跨ぎでも発注・請求書を含めて全コピー

- 長所: 新案件に全情報が揃う。
- 短所: 請求書・添付ファイルのコピーは台帳（10年保存）や採番の整合を壊す。

## 決定内容

選択肢Bを採用する。

- 受注一覧: 期タブは各期のみ（全期間なし）。表示順は案件ID「WW{期2桁}-{連番3桁}」を期、連番の数値昇順とし、
  旧形式・未採番は後ろに ID 昇順で並べる（src/lib/project-order.ts）。通知のディープリンク（?q=）は
  全案件から該当案件を探してその期タブへ切り替え、見つからなければ現在の期のままにする。
- 金額: 予定売上・契約金額は受注一覧では読み取り専用。projects.create / update / changeDeliveryMonth は
  amount・plannedAmount を受け付けず、編集経路は projects.updateRevenue（工事計画用）のみ。
- 期跨ぎ（crossesFiscalYear が true）: 旧案件はそのまま残してステータスを「オーダー移行」にし、
  新しい期で新規採番した案件へ案件項目と発注のみをコピーする。支払番号は新案件IDで採番し直し、
  請求書・保存済みPDF・案件／発注の添付・工事ID・支払ステータス（未払いへ戻す）は引き継がない。
  監査ログは新旧両案件に残す。同一期内の変更は従来どおり移動。

## 決定の理由

期ごとの実績（請求書・支払）は旧期に残すべきで、移動では集計が変わる。一方で請求書は台帳として保存義務があり
コピーすべきでない。発注だけを複製すれば、新期の工事計画を続けられる。

## 影響

### ポジティブ

- 期別集計が過去分を保ったまま新期の計画を引き継げる。
- 受注一覧の金額が工事計画と食い違わない（単一の編集経路）。

### ネガティブ

- 旧案件（オーダー移行）に発注が残るため、発注・案件を集計するクエリは status が「オーダー移行」の案件を
  除外する必要がある（reporting.ts は除外済み。dashboard.ts・receipts.ts・工事計画／支払管理の発注一覧は要確認）。

### フォローアップタスク

- [ ] dashboard / receipts / 発注一覧系クエリで「オーダー移行」案件を除外する。
- [ ] 期跨ぎコピーの統合テスト（DB 付き環境）を追加する。
