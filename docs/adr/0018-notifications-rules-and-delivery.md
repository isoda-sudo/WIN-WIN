# ADR-0018: 通知の種類・条件・開封状態・遷移と、毎朝10時の開封済みリセット

## メタ情報

- **ステータス**: 提案中(Proposed)
- **日付**: 2026-10-27
- **決定者**: Claude Code（承認: 人間レビュアー）

## コンテキスト（背景と課題）

通知は、画面右上のベルを開いたときに、その時点のデータから計算して表示する（送信はしない。メール・プッシュ・定期送信は無い）。開封状態はユーザーごとにDB（`notification_opens`）へ保存する。顧客から、次の要望・指摘があった。

- 期日が近いだけの通知は不要（期日を過ぎたものだけ通知する）
- 契約未締結の通知は、工期が終わっても、契約書が締結されるまで出し続ける
- 条件を満たしている間は、毎朝10時に、再び未開封として出してほしい
- 「詳細を見る」で、確実にその対象のデータへ移動し、時間がかからないこと

## 決定内容

**通知の種類と条件**（`src/lib/notification-rules.ts`、`src/server/api/routers/dashboard.ts`）

| 通知 | 条件 | 対象 |
| --- | --- | --- |
| 支払期日超過 | 未払いの発注の支払期日を過ぎた | 管理者・経理 |
| 入金期日超過（売上管理表） | 売上管理表の行（案件ごと。入金期日は最後の請求書）の入金期日を過ぎ、案件が全額入金済みでない | 管理者・経理 |
| 入金期日超過（請求書） | 分割請求で、最後より前の請求書の入金期日を過ぎた。ステータスが「分割入金済み」の案件は、最後より前の請求書は入金済みとみなして通知しない | 管理者・経理 |
| 着工前アラート（契約未締結） | 工期の開始日を過ぎ、契約書が無い。**工期が終わっても、締結されるまで出し続ける**。失注・オーダー移行は除く | 全員 |
| 未発注アラート（注文書・請書） | 工期中で、注文書が未発行、または請書が未受領の発注（担当者ごとにまとめる） | 全員 |
| 請求漏れアラート | 引渡月が終わった（翌月1日以降）のに、案件が「受注」のまま | 管理者・経理 |
| 支払期日の変更（通常と異なる） | 支払条件から計算した期日と違う期日が設定されている | 管理者・経理 |
| 月次確定ロック漏れアラート | 引渡月の翌月20日を過ぎても、確定（ロック）が未完了 | 管理者・経理 |

- **廃止**: 「支払期日接近」「入金期日接近」（期日の7日前から当日までの通知）
- 税理士・社労士には通知を出さない

**開封状態**: キーは「種類:対象:日付」。一度開封すると、条件が続いていても、翌日以降も開封済みのまま。

**毎朝10時のリセット**: Vercel Cron（`vercel.json`、UTC 01:00 = 日本時間10:00）が `/api/cron/reset-notifications` を呼び、全員の `notification_opens` を削除する。条件が続いている通知は、未開封として出し直される。`CRON_SECRET`（任意）を設定すると、`Authorization: Bearer` を必須にする。未設定の間は Vercel Cron の User-Agent で受ける。無料プラン（Hobby）では、実行時刻が指定の前後1時間でずれる。

**遷移（「詳細を見る」）**: 通知ごとに、対象（`project-ID` / `order-ID`）と、その対象が載る年月を持つ。遷移先のURL（`?focus=…&q=ID&month=YYYY-MM`）で、画面を開いた時点でIDによる検索（1件）と年月が入った状態になり、一覧の読み込みを待たずに対象の行だけを描画する。複数案件の通知（確定ロック漏れ・未発注）は、年月と期だけを合わせ、対象の行までスクロールする。行の点滅・色変更はしない。移動後はURLの指定を外す（`src/lib/use-focus-deep-link.ts`）。

**ベル**: 「すべて」「未開封」の切り替え（件数は未開封のタブにのみ表示）、カード形式。未開封の背景は、左メニュー選択時と同じ色（`secondary/15`）。

## 影響

### ポジティブ

- 通知から対象データへ、確実に素早く移動できる
- 条件が続く限り、毎朝、未開封として出る

**入金期日の通知の2つの単位（2026-10-27 追記）**: 売上管理表単位（案件の行）と請求書単位（分割請求の、最後より前の請求書）の両方で通知する。最後の請求書は売上管理表単位でのみ通知し、同じものを二重に通知しない。売上管理表の入金ステータスに「分割入金済」を追加した（案件のステータスは「分割入金済み」）。売上管理表の月の絞り込みは、分割請求では、どの請求書の入金期日でも行を表示する（請求書単位の通知から開いても、行が見つかる）。通知の識別には、請求書のidまで含める（同じ期日の請求書があっても重ならない）。

### ネガティブ・未解決

- 通知の未入金額は税込（請求書の合計）、売上管理表の契約金額は税抜で、同じ案件の金額が食い違う（現状のまま運用する）
- 「分割入金済み」では、どの請求書が入金済みかは持たない（最後より前を入金済みとみなす）。入金額（実績）は、全額入金済みのときだけ契約金額として数え、分割入金済みの間は0
- 開封状態の保存は、毎朝のリセットまで続くため、1日のうちに条件が解消して再発した通知は、同じ日のうちは、開封済みのまま
