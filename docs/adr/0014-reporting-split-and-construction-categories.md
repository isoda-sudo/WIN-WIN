# ADR-0014: レポーティングの顧客・発注先分離と工種マスタの整理

## メタ情報

- **ステータス**: 提案中(Proposed)
- **日付**: 2026-10-13
- **決定者**: Claude Code (承認: 未定)

## コンテキスト（背景と課題）

レポーティングの「顧客・発注先分析」「企業別発注金額一覧」は顧客側と発注先側が同じ画面・同じ集計に混在しており、案件ごとの粗利率や発注先への発注の偏りを読み取りにくかった。また工種マスタは並び順を画面から変えられず、建築業界向けの標準的な分類も未整備である。発注（orders.category）は工種を名称で参照している。

## 検討した選択肢

### 選択肢A: 既存タブ内でフィルタを増やす

- 長所: 画面追加が不要
- 短所: 顧客と発注先の指標が混ざったままで、権限・フィルタ・グラフを個別に設計できない

### 選択肢B: 顧客別・発注先別を別ルートに分離する

- 長所: 画面ごとに目的・フィルタ・グラフを最適化できる。純粋関数に集計を切り出してテストできる
- 短所: ルートと tRPC プロシージャが増える

## 決定内容

選択肢Bを採用する。

- /reporting/customers（顧客別分析）と /reporting/vendors（発注先別分析）を追加し、/reporting からは該当タブを削除して入口カードを置く。権限は /reporting の layout（admin, accounting, staff, viewer）を継承する。
- 粗利 = 売上（projects.amount）− 案件の発注の決定金額（orders.decided）の合計。粗利率 = 粗利 ÷ 売上（売上が 0 または null なら null、小数第1位に丸める）。削除済み案件、オーダー移行、失注は除外する。期は引渡月の期で絞る。
- 発注先の偏りは発注金額シェア、上位3社・5社シェア、ハーフィンダール指数（シェア%の二乗和、0〜10000）で示す。発注先なしの発注は除外し、工種で絞り込める。
- （撤回: 2026-10-15）工種マスタの並び替え機能は要望に無かったため削除した。以下は当初の決定: 工種マスタは表示順（order）をドラッグで並び替え、categories.reorder（admin）で1トランザクションで書き直す。建築業界向け分類の投入スクリプトは冪等で、自動実行しない。

## 決定の理由

指標の定義がクライアント決定済みのため、集計を純粋関数にして単体テストで固定できる。スキーマ変更は不要（categories.order は既存）。

## 影響

### ポジティブ

- 顧客側・発注先側の分析が独立し、目的に沿ったグラフが見られる
- 工種の並びを画面から管理できる

### ネガティブ

- 分類リストは仮であり、クライアントの Slack での決定後に更新が必要
- 工種名を変更しても orders.category は書き換わらない（名称参照）

### フォローアップタスク

- [ ] クライアント確定後に scripts/seed-construction-categories.ts のリストを更新する
- [ ] 投入前に --check で発注側にあってマスタに無い工種を確認する
- [ ] サイドバーに /reporting/customers と /reporting/vendors のリンクを追加する

## 参照

- ADR-0007: 支払スケジュールの定期支払と分類

## 追記: 工種マスタは現行の登録分のみを使う

クライアント回答（「あるものだけでいい」）により、工種マスタに新しい分類（金物工事・木工事・その他など）は追加しない。`scripts/seed-construction-categories.ts` の追加リストは空にし、`--check`（発注で使われている工種がマスタにあるかの読み取り専用チェック）だけを残す。
