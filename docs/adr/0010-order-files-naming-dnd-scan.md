# ADR-0010: 受注添付書類のドラッグ＆ドロップ・自動命名・撮影PDF化

## メタ情報

- **ステータス**: 提案中(Proposed)
- **日付**: 2026-10-13
- **決定者**: Claude Code (承認: レビュアー)

## コンテキスト（背景と課題）

工事計画（orders-list）の請書・請求書は、クリックでファイルを選んで手動命名のままアップロードしていた。次の要望がある。

- PDF をドラッグ＆ドロップで添付したい。
- 電子帳簿保存法（電帳法）の検索要件（日付・金額・取引先）を満たす保存名にしたい。ユーザーが名前を自由に付けられると要件が崩れる。
- 現場でスマホ撮影した複数ページの書類を PDF にして添付したい。
- 売上（予定／決定）の編集は projects.updateRevenue に一本化された（旧 projects.update は金額を受け付けない）。
- 制約: Vercel のリクエストボディ上限 4.5MB のため PDF は 3MB まで（data URL 化で約 1.33 倍）。

## 検討した選択肢

### 選択肢A: サーバーが保存名を決め、日付・金額は別列に保存（採用）

- 長所: 名前を改変できない。列があるので検索要件（日付・金額・取引先）を DB で満たせる。
- 短所: order_files に列を追加する（additive のみ）。

### 選択肢B: ユーザーがファイル名を入力

- 長所: 実装が軽い。
- 短所: 表記ゆれ・誤記で検索要件を満たせない。

### 撮影PDF化の方式

- 選択肢1: pdf-lib（MIT）でブラウザ内生成（採用）。サーバー負荷なし・追加インフラなし。
- 選択肢2: サーバー側で変換。ボディ上限と負荷の問題があり不採用。
- 選択肢3（運用での代替。調査結果）: Adobe Scan、または OS 標準のスキャナ機能（iOS の「ファイル」アプリのスキャン、メモアプリの書類をスキャン、Android の Google ドライブのスキャン）で PDF 化してからアップロードする。追加実装なしで高品質（自動トリミング・補正）だが、操作が 2 アプリにまたがる。本機能の「撮影してPDF化」はアプリ内で完結させる簡易手段で、上記の運用手段も引き続き使える（PDF を選ぶ／ドロップする経路は従来どおり）。

## 決定内容

1. 請書／請求書セルに FileDropzone（label と input type=file による、ドロップ対応の共通部品）を導入し、PDF のみ・3MB 以下を受け付ける。
2. アップロード前に「書類の日付」「書類の金額」を入力させ、サーバーが `YYYYMMDD_取引先_金額_書類名.pdf` を決める（書類名は請書／請求書）。日付・金額は order_files.doc_date（text）と order_files.doc_amount（bigint、0 以上の CHECK）にも保存する。既存行は NULL のまま旧名を維持する。
3. 「撮影してPDF化」ダイアログで画像を並べ替えて pdf-lib で 1 つの PDF にし、同じアップロード経路（日付・金額ダイアログ→サーバー命名）に流す。
4. 売上の編集は projects.updateRevenue を使う。

新規依存: pdf-lib 1.17.1（ライセンス: MIT。Hard Rule 11 に基づき明記）。ブラウザ側で動的 import する。

## 決定の理由

名前をサーバーで固定し日付・金額を列で持つことで、画面・ダウンロード・検索のすべてで要件を満たせる。ブラウザ内生成は 3MB 制限と相性がよく、運用側の代替手段（Adobe Scan・OS 標準スキャナ）とも矛盾しない。

## 影響

### ポジティブ

- 電帳法の検索要件（日付・金額・取引先）を満たす保存名と検索用の列が揃う。
- スマホだけで複数ページ書類を添付できる。

### ネガティブ

- uploadFile の入力が変わる（docDate・docAmount が必須、filename は廃止）。旧クライアントは失敗する。
- 3MB に収まらない大量ページは作成できない（ページ数を減らす）。
