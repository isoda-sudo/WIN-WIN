# ADR-0017: 排他制御（支払い予定表・売上管理表・工事計画）をサーバーで強制し、最後の操作から15分で解除する

## メタ情報

- **ステータス**: 提案中(Proposed)
- **日付**: 2026-10-27
- **決定者**: Claude Code（承認: 人間レビュアー）

## コンテキスト（背景と課題）

顧客から、「他の人が開いていても閲覧は常にできるが、アップロード・更新は同時に1人だけにしたい（順番待ちにはしない）」という要望があった。最初の実装は画面側の無効化（一覧の表だけを閲覧専用にする）で、次の問題があった。

- サーバーが更新を止めておらず、画面の無効化を通らない操作（モーダル、別経路のAPI）で更新できた
- 同じユーザーが別のタブで開いた場合、同じ人として扱われ、両方が編集できた
- 画面を開いている間はハートビートで編集権を持ち続け、操作せずに放置しても解除されなかった
- タブを閉じたときの手放す通信が打ち切られ、解除されないことがあった

## 検討した選択肢

### 選択肢A: 画面側の無効化のみ（従来）

- 長所: 実装が小さい
- 短所: サーバーで止まらないため、モーダルや別タブ・直接のAPI呼び出しから更新できる

### 選択肢B: サーバーで更新を拒否し、画面側も閲覧のみにする

- 長所: 排他が実際に効く。画面側は理由の表示と無効化に専念できる
- 短所: 更新APIが画面（scope）を知る必要があり、ヘッダの付与とDB参照が増える

## 決定内容

選択肢Bを採用する。

- **対象画面（scope）**: 支払い予定表（`payments`）、売上管理表（`receipts`）、工事計画（`plan:{案件ID}`）の3画面のみ。受注一覧など他の画面は対象外で、そこからの更新も止めない
- **編集権の取り方**: 最初に画面を開いた1名（1つのタブ）だけが編集できる。後から開いた人・同じ人の別タブは閲覧のみ（順番待ちはしない）。`edit_locks.client_id` にタブごとの識別子を持つ
- **サーバーでの強制**: 排他制御のある画面からの更新系API（tRPCのmutation）は、リクエストヘッダ `x-edit-scope` / `x-edit-client` を見て、別の人（または同じ人の別タブ）が編集中なら `FORBIDDEN`（「現在 〇〇 さんが編集中のため、更新できません」）で拒否する。全手続きが通る `timingMiddleware` から判定する。`editLocks.*` と `dashboard.*`（通知の開封）は対象外。アップロードも更新系APIのため同様に拒否される
- **画面側**: 3画面に「現在 〇〇 さんが編集中です」の帯を出す（ほかの画面には出さない）。一覧の表と、ダイアログ（`Dialog` / `AlertDialog`）の入力欄・更新ボタンを無効にし、ダイアログ上部に注意書きを出す。閉じる・プレビュー・ダウンロードは使える
- **解除の条件**: 編集者の最後の操作（クリック・キー入力・スクロール・タッチ）から**15分**、または画面（ハートビート）が15分途絶えたとき。画面を閉じる・再読み込みする・別メニューへ移動するときは、その場で手放す（閉じる際は `keepalive` で送る）。`edit_locks.activity_at` が最後の操作の時刻
- **解除後**: 閲覧のみだった人の「編集中」の表示が消え、次の確認（20秒ごと）で自動的に編集権を取る

## 決定の理由

- 画面側の無効化だけでは、モーダルや別タブから更新でき、排他にならない。サーバーで拒否すれば、画面の作りに関係なく守れる
- 別のタブで開いて放置された編集権が、何時間も残るのを避けるため、最後の操作から15分で解除する。ハートビートの途絶えは、裏のタブでブラウザが通信を間引いて操作中の人から編集権を奪わないよう、同じ15分にした
- 短時間（60秒）の解除は、別のタブで作業中の人から編集権を奪うため採らない

## 影響

### ポジティブ

- 3画面では、他の人が編集中のあいだ、更新・アップロードが実際にできなくなる
- 画面を離れたときに、15分待たずに引き継げる

### ネガティブ

- 更新のたびに（ヘッダ付きの場合）`edit_locks` を1回参照する
- 受注一覧からは、同じデータ（発注など）を更新できる。必要になった場合は、受注一覧にも scope を付ける
- ダイアログの無効化は、ボタンの文言で更新系かを判定する（文言に当てはまらないボタンは、画面では有効のままだが、サーバーで拒否される）

- [ ] 15分で解除される様子を、実際に待って画面で確認する
- [ ] 受注一覧への適用の要否を決める
